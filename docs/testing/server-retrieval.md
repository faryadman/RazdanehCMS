# اصلاح واکشی سرورها در پنل

تاریخ: ۲۰۲۶-۱۰-۱۹. شاخهٔ `fix/server-retrieval` از `f25783f`؛ کاربر محل مشکل را «فهرست یا جزئیات سرورها در پنل» مشخص کرد. این تغییر اصلاح مسیر خواندن و نمایش است؛ الگوریتم انتخاب سرور Android، job، DNS، schema و مسیرهای write تغییر نکرده‌اند.

## بازتولید و علت‌های تأییدشده

در SQL Server 2022 یک‌بارمصرف با repository و سرویس واقعی و دادهٔ ساختگی، اجرای اولیهٔ ۱۱ تست، ۶ شکست و ۵ موفق داشت:

- projectionهای مستقل فهرست و آمار، ConfigKey، ConfigValue، ZoneId و ZoneIdLastSynced را مقدار نمی‌دادند؛ DomainDateTime فهرست هم پیش‌فرض باقی می‌ماند.
- GenericRepository.SingleOrDefaultAsync، navigation گروه را بارگیری نمی‌کرد. در context تازه، Detail با group:null برمی‌گشت؛ مسیر HTTP جزئیات هم همین نقص را نشان داد.
- appId ناموجود در فیلتر به NullReferenceException می‌رسید. middleware قدیمی آن را به HTTP400 تبدیل می‌کرد.

ترجمهٔ query فعلی روی SQL آزمایشی موفق بود؛ خطای ترجمهٔ AutoMapper به‌عنوان علت اثبات‌شده گزارش نمی‌شود. query plan یا سازگاری SQL واقعی تولید در دسترس این تست نبوده است.

تست‌های JavaScript روی نسخهٔ اولیه نیز این ایرادها را نشان دادند: JSON خراب یا نبود مسیر outbounds[0] رندر را قطع می‌کرد، گروه null محافظ نداشت، درج تکراری به DataTables درخواست می‌شد، مقادیر در HTML escape نمی‌شدند، فرم ویرایش دادهٔ قدیمی attributeهای جدول را مصرف می‌کرد و هر شکست واکشی را خطای اینترنت می‌نامید. این‌ها تست تابع با بدل DOM/DataTables هستند، نه آزمون مرورگر و plugin واقعی.

## اصلاحات

`ServerReadProjection.WithStatistics` نگاشت کامل و قابل‌ترجمهٔ مشترک برای فهرست و آمار است؛ DTO تازه‌ای به API افزوده نشده و کل graph لاگ‌ها بارگیری نمی‌شود. آمار فقط log فعال را می‌شمارد و برای نبود log همچنان null است. خواندن فهرست بدون app filter در تست با یک SELECT و بدون tracking انجام شد.

`IServerRepository.GetActiveWithGroupAsync` و implementation آن گروه را صریح و بدون tracking بارگیری می‌کنند؛ Detail عددی و رشته‌ای از یک مسیر مشترک می‌خوانند. parsing شناسهٔ رشته‌ای، ترتیب Id صعودی فهرست، فیلتر active/ad/group/app و معنای availability حفظ شده‌اند.

برای appId ناموجود، BadRequestException با پیام فارسی داده می‌شود: HTTP400 و envelope خطای قبلی حفظ شده، ولی متن خطای null انگلیسی به «برنامه یافت نشد» تبدیل می‌شود. فیلدهای قبلاً null یا تاریخ پیش‌فرض در فهرست/آمار و group جزئیات اکنون مقدار واقعی دارند؛ این اصلاح داده است و ادعای یکسان‌بودن بایتی تمام پاسخ‌های معیوب قدیمی نمی‌شود.

پنل JSON خراب را با هشدار متنی در همان ردیف نشان می‌دهد و بقیهٔ ردیف‌ها ادامه می‌یابند. مسیرهای optional و گروه غایب با علامت «—» نمایش داده می‌شوند. متن‌های پویا پیش از قرارگرفتن در HTML escape می‌شوند. رندر برای هر سرور یک درج و در پایان یک draw درخواست می‌کند. فرم ویرایش نام، محل و IP را از پاسخ تازهٔ Detail می‌گیرد؛ نتیجهٔ غیرآرایه‌ای واکشی، جدول قبلی را پاک نمی‌کند.

## نتیجهٔ اعتبارسنجی

- ۱۴ تست SQL واقعی: فیلترها، گروه‌های برنامه، برنامهٔ بدون گروه، فهرست خالی، رابطهٔ گروه، تمام فیلدهای Config/zone/date، آمار فعال، نبود tracking، یک SELECT، شناسهٔ رشته‌ای، inactive/missing و درخواست HTTP پنل با repository واقعی؛ همگی موفق.
- ۳۲ تست قرارداد قبلی: همگی موفق، هیچ snapshot بازنویسی نشد؛ metadata مربوط به ۱۲۱ اکشن و ۴۴ DTO ثابت است.
- ۷ تست JavaScript رندر/واکشی/فرم: همگی موفق؛ بدون کتابخانهٔ npm اضافی.
- build هر ۸ پروژهٔ solution موفق؛ اجرای نهایی incremental با ۱۳ warning و صفر error. advisoryهای قبلی وابستگی همچنان بازند.

```bash
dotnet test RazdanehCMS.sln --no-restore -m:2
node --test tests/frontend/server-retrieval.test.cjs
dotnet build RazdanehCMS.sln --no-restore -m:2
```

مجموع: ۴۶ تست .NET و ۷ تست JavaScript، بدون skipped. برای ثبت TRX چند پروژه از `--logger trx` با نام پیش‌فرض یکتا استفاده کنید؛ نام ثابت مشترک می‌تواند نتیجهٔ یک پروژه را بازنویسی کند. شمارش هر دو پروژه از خروجی همان اجرای موفق تأیید شد.

Testcontainers تصویر SQL Server با digest ثابت و رمز تصادفی نگهداری‌شده فقط در حافظه ایجاد و پس از اجرا حذف می‌کند. هر تست دیتابیس مجزای خودش را دارد. appsettings، کلید Cloudflare یا اتصال SQL تولید خوانده نمی‌شود؛ Program اصلی، seed و worker اجرا نمی‌شوند. Docker و دسترسی دانلود تصویر آزمایشی پیش‌نیاز این suite است. workflow هر دو suite را روی PR اجرا می‌کند؛ نتیجهٔ CI باید از run واقعی بررسی شود.

## محدودیت و بازگشت

این بررسی علت همهٔ رخدادهای تولید را اثبات نمی‌کند؛ نمونهٔ خطای واقعی، نسخه/compatibility level دیتابیس تولید و تست کامل مرورگر موجود نیست. JSON خراب هنوز می‌تواند از مسیرهای write قدیمی ذخیره شود؛ این تغییر فقط نمایش مقاوم می‌سازد و جای validator نیست. کش و انتخاب سرور Android، امنیت دسترسی و DNS خارج این اصلاح‌اند. بازگشت با revert commit اصلاح ممکن است؛ migration یا تبدیل داده ندارد.
